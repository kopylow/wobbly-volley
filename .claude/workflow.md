# Workflow: Wobbly Volley

* **Backlog:** `PLAN.md` section 9, milestones M0 to M11 in order, with M2b after M2. The first unticked one is next. A milestone that waits on another machine or person carries "waiting <on whom>" in its line and is skipped. Done mark: `[x]` and "done <date>" in the commit that finishes it.
* **Binding:** `PLAN.md` sections 0 (rules), 3 (decisions, closed) and 6 (architecture). The API authority is `.claude-plugin/types/claude-code/index.d.ts`, which the engine lays at every load. Section 5 is the map.
* **Where results go:** prototype numbers into section 10, kit and API facts into section 5, deviations and findings with date and milestone into section 11.
* **Checks before a tick:** `claude plugin validate .`, `claude plugin test .`, `npx -y -p typescript tsc -p .`.
* **Laying the types without a session:** from any other folder, in PowerShell (Git Bash rewrites the slash command into a path), `claude -p "/volley" --plugin-dir C:\projects\ClaudeyVolley --no-session-persistence --setting-sources project`. It runs no model turn.
* **On Linux or macOS:** the same headless line from any other folder in any shell, with the folder's own path; `./dev.sh` stands in for `.\dev.ps1`. The project reaches those machines through the repo (`PLAN.md` section 7, "P4 on the other systems").
* **Manual checks:** the user, in a session started with `.\dev.ps1` (`-Only <prototype>` for one prototype alone).
* **Probes:** kit behaviour is checked with a throwaway `tests/zz-probe.test.ts`, run alone (`claude plugin test --file tests/zz-probe.test.ts .`, the test file's `console.log` lines show in the output, a hooks module's do not: read those back through a `command.run` hook of the probe) and deleted afterwards. A probe that needs hooks of its own runs in a scratchpad copy of the mod; give `--file` and the folder as absolute paths there. The core runs in Node for tuning and measuring (`npx -y tsx <scratch file>`, importing the core by absolute path, `C:/projects/ClaudeyVolley/core/...`); M5 tuned the AI that way. The tuning sheet `npx -y tsx tools/tune.ts [NAME=value ...] [quick]` prints what the constants give in play (jumps, the ball's flight, rally lengths, the ball above the view, the human stand-in against each level, the pairings) in about 10 s, on a copy of the core under the system temp, so it writes nothing into the mod's folder.
* **Checking the tests:** before a tick, break the new code on purpose, one break at a time, in a copy outside the repo (the scratchpad) and run `claude plugin test <copy>`; a break no test catches is either a missing test or code that changes nothing (`PLAN.md` section 11 lists each round). Six copies at once time single tests out at the kit's 5 s, and two can still push the long AI test past it: a timeout is no verdict, so run that copy again alone.
* **Git:** branch `main`, commits straight to `main`, staged by path. Remote `kopylow/wobbly-volley`. Its history starts with the 1.0.0 release commit (`PLAN.md` section 11).
* **Releases:** a release raises `version` in `.claude-plugin/plugin.json` and `VERSION` in `hooks/register.tsx` together. Installed users get a new copy only when the version changes (`PLAN.md` 5.1 row 88). The mod's `name` stays as it is: it is what installs are recorded under.
* **Estimates:** `PLAN.md` keeps no hour figures. A fresh estimate goes into the milestone's line when it is worked.
